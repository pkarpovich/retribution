# Frozen test data

Every test reads its hero data from here, never from `src/data/`.

`src/data/heroes.json` is refreshed twice a week by the update workflow, so a
test that imports it is a test whose result changes when nobody has touched the
code. That is not a test. It is a monitor wearing a test's clothes, and it fails
the build on the day the meta moves rather than the day someone breaks the
engine.

These files are snapshots taken on 2026-07-30. They do not get refreshed. When a
test asserts a number, that number is a property of the code, and a change in it
means someone changed the code.

| File | Taken from | Why it is frozen |
| --- | --- | --- |
| `heroes.snapshot.json` | `src/data/heroes.json` | Refreshed Mon/Thu from the live API - tiers, scores and win rates all move |
| `liquipedia-heroes.snapshot.json` | `src/data/liquipedia-heroes.json` | Regenerated by hand, but changes when the wiki does |
| `pro-drafts.snapshot.json` | `src/data/pro-drafts.json` | Already static, copied here so tests have one place to look |

`src/utils/__tests__/noLiveData.test.ts` fails the suite if any test starts
importing `src/data/` again, so the rule holds without anyone remembering it.

## Refreshing a snapshot

Only when a test genuinely needs newer data - a new hero the engine must handle,
a schema change. Copy the file across, run the suite, and expect to update the
numbers the benchmark asserts in the same commit. Those numbers moving is the
point: it should be a deliberate edit with a reason in the message, not
something that happens to the build on a Thursday morning.
